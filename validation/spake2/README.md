# Independent SPAKE25519 expected bytes

`boringssl-spake2-vectors.json` is copied unmodified from Flyfish233/spake2
`b837aba27bebc1050965fa124c2efa54b4e4544a`, `test-vectors/legacy/`.
Original fixture source: Flyfish233/spake2-java
`809ad7aa731f475c07763b1ad2c165ae192dfb5f`. Its GPLv3 license is retained here;
this data is confined to tests and is not compiled into Kadb runtime artifacts.

SHA-256: `94ed5b9c564794eac6d2494966ff3ae479d872171f6a70286f504cbe4bfe8d94`.

The C oracle uses google/boringssl
`9e04aed2d1652441d2c84e85ed21acc05e053260`; the fixture records entropy,
compressed point messages and final unconfirmed keys. Kadb replays five fully
hardened exchanges, including the ADB NUL-terminated identities and bit-255
scalar carry boundaries. The expected bytes are copied directly from that
independent oracle fixture; they are not generated by the implementation under test.

`PairingSpakeVectorTest` executes those fixtures through Kadb's **production**
`PairingCrypto` wrapper. `PairingSpakeCompatibilityTest` is a separate integration
check for shared Legacy Bob, HKDF, AES-GCM and nonce framing; it is not represented
as an independent cryptographic implementation. The old Java/BoringSSL-derived
peer remains test-only for full TLS exporter + pairing differential tests.

The source dependency's previous validation is a reference, not a test run in this
Kadb experiment. Only current reports/jobs establish execution on a target.

## Reference re-executed in this Kadb experiment

`oracle-reexecution.json` records a new C reference execution. It intentionally
separates the fixture oracle (`9e04aed2…`) from the **executed** Native backend
reference (`5b83e5d1abf0ae0033ae52ab579d906b67633b2c`). Seven exchanges / fourteen
endpoints and four peer-input cases matched byte for byte. This is independent C
reference reexecution; Kotlin/Native or device execution is a separate claim.

The current BoringSSL source archive is
<https://codeload.github.com/google/boringssl/tar.gz/5b83e5d1abf0ae0033ae52ab579d906b67633b2c>,
SHA-256 `4117ae02de040d4469284673ed63a14e648af7c3974aa9e85bcef2975a9c9ea8`.
The Native backend build verified that archive before it was reused here.

`legacy_oracle.cc` is copied unmodified from the pinned SPAKE2 source; it is
AGPL-3.0-only with its original notice. It includes the separately supplied
BoringSSL implementation in a test translation unit and replaces only its random
byte call with test entropy. It is never linked into Kadb's runtime. The build
command and hashes of harness, source file, crypto archive and executable are
recorded in the JSON report.

To rebuild and re-run using the current backend's verified source/archive:

```sh
python3 validation/spake2/replay_oracle.py \
  --oracle /tmp/kadb-spake-oracle \
  --report /tmp/kadb-spake-oracle-result.json \
  --reference-source /path/to/verified/boringssl \
  --reference-commit 5b83e5d1abf0ae0033ae52ab579d906b67633b2c \
  --libcrypto /path/to/native/build/lib/libcrypto.a
```

The script compiles the C test harness, executes it, and fails on any mismatch.
The deliberately malformed peer case that the historical decoder accepts is
compared to its actual reference result, not renamed into an expected rejection.
